## Quoted model language is not a project claim

The files marked *verbatim LLM output* above contain causal phrasing produced by
the models — for example Gemini writing that a metric gap "causally implies"
an outcome, or that a model "causally learns and replicates" historical
disparities. **Those are transcripts, not findings.** This project makes no
causal claim anywhere:

- `map_root_causes()` performs rule-based inference from metric values and
  feature correlations. It does not identify causal structure.
- No intervention, instrument, or counterfactual estimand is computed anywhere
  in the pipeline.
- The metrics are associational: disparate impact, demographic parity
  difference, equal-opportunity difference, average odds difference, Theil.

Guardrail 6 of `docs/RESEARCH_STAGING_PROMPT.md` forbids overclaiming, and the
Stage 5 overclaim grep (`rg -i "compliant|causal|recompute"`) is the check. The
grep intentionally still matches these files: the correct outcome is that
quoted model language *remains quoted*, not that it gets edited out of the
record. Editing a transcript to remove an overclaim would falsify the evidence
that the model made it — and "the LLM reaches for causal language unprompted"
is itself a Track Q/H observation worth keeping.

One genuine overclaim in **our own** prose was found and fixed by that grep:
`qualitative_analysis.py` described its root-cause mapping as "interpretable
causal diagnostics". Reworded to "root-cause diagnostics (rule-based inference
from metrics and feature correlations, not causal identification)".

## No legal or compliance conclusion

ECOA, Regulation B and the four-fifths rule appear as *decision context* for
why a threshold matters in lending. Nothing here is a compliance determination.
A disparate-impact ratio below 0.8 is a screening signal that regulators and
practitioners use, not a finding of unlawful discrimination.

## Regenerating

```bash
python3.11 run_pipeline.py --datasets german_credit hmda lending_club --steps qualitative
python3.11 scripts/report_track_q.py
python3.11 scripts/evaluate_track_h.py          # add --judge for the rubric score
python3.11 scripts/visualize_track_q.py
```

Always pass all three datasets. `run_pipeline.py`'s consolidation step rebuilds
the cross-dataset files from **only** the datasets passed via `--datasets`, so
a subset run silently leaves them holding a subset.
