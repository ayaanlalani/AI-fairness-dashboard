\section{The question}

When a fairness audit prints a number, say ``disparate impact $0.94$,'' does
that number measure what its name says? We built a complete fairness audit of
consumer credit and mortgage models ($1{,}000$ and $10{,}978$ real
applications, every applicant scored out-of-fold), and then audited the audit.

\section{The result}

\textbf{The same model, judged on the same applicants, passes or fails
depending on settings that appear nowhere in the output. Nine measurements in
this one audit computed something other than the construct they were named
for, and every one produced a clean, reassuring result.} The four sharpest:

\textbf{(1)} A library constructor default (\texttt{favorable\_label=1.0},
AIF360 0.6) decides which outcome of a loan is \emph{good}. On a
default-coded target it reports the disadvantaged group as favoured:
$\mathrm{DI}=1.2072$ where the oriented value is $0.9862$.

\textbf{(2)} The age attribute decides which age question is asked. Banded at
$40{+}$ (a threshold imported from employment practice) the model reads
$0.9791$: clean. On the $62{+}$ boundary the mortgage data ship a dedicated
flag for, \emph{the same model over the same people} reads $\mathbf{0.8897}$,
the largest age disparity present. The public age bands straddle 62, so no
banded attribute can ever see it.

\textbf{(3)} The reporting policy decides what small groups can do to the
verdict. At the audit size we first used ($m{=}2{,}196$ of $10{,}978$),
$2{,}000$ resampled audits show: point estimates falsely clear a
truly-violating subgroup in $\mathbf{83.8\%}$ of draws; reporting floors never
false-clear but name the wrong worst-treated group in $\mathbf{100\%}$
(they never report it); honest intervals must abstain in $90.3\%$.
\emph{Every} policy that shows small cells is usually wrong; every policy
that hides them is silently blind.

\textbf{(4)} Our own checking instruments did it too: a refusal detector
defining refusal as \emph{under 40 characters} flagged six correct terse
answers and helped block a provider, and most of a cross-model ``prompt
sensitivity'' spread ($14.7$ vs.\ $0.0$ points) came from our scorer
penalising instructed brevity; excluding that cycle, $6.7$.

\section{What it means}

A fairness verdict is therefore not a property of the model alone; it is a
property of the model plus a configuration (label orientation, attribute
banding, reporting policy, reference group, detector thresholds) that is set
silently and appears nowhere in the output. Two consequences. \textbf{A
fairness number you are handed is uninterpretable without its configuration}:
the same data honestly support ``worst cell $0.67$,'' ``worst cell $0.90$,''
or ``worst cell unknowable.'' And \textbf{the errors point one way}: every
wrong verdict we measured erred toward false clearance, the reassuring
direction nobody rechecks. An audit should ship its configuration the way
results ship error bars; the section below is that record.

\section{What an audit must record}

The favorable outcome, stated explicitly. The interval, $n$, and reference
group beside every ratio, plus every suppressed cell. The definition's source
beside every threshold. The reporting policy by name. Population construction
(we dropped $45.1\%$ of the raw file before any metric ran). And an
adversarial test for every mechanical gate, starting where the correct answer
is unusual. None of this is hard; all of it is currently optional.
